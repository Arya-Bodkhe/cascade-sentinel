# CASCADE SENTINEL: Comprehensive Loophole & Vulnerability Audit

This audit document catalogs all identified data, policy, algorithmic, and user-experience loopholes, their severity, and the verified architectural fixes implemented in CASCADE SENTINEL for Pune district.

---

## 1. Data Layer Audits

| ID | Issue Description | Severity | Hazard / Operational Risk | Architectural Fix & Proof |
| :--- | :--- | :--- | :--- | :--- |
| **DATA-01** | **UTC vs. IST Timezone Mismatch** | **CRITICAL** | Open-Meteo reanalysis files store timestamps in UTC (`+00:00`), while IMD daily rainfall records correspond to the 08:30 IST synoptic observation window. Comparing raw UTC against IST calendar dates introduces a 5.5-hour phase error, misaligning diurnal convective peaks and rainfall accumulations. | In `src/data/loader_openmeteo.py`, all UTC timestamps are explicitly parsed with timezone awareness and converted to `Asia/Kolkata` (`+05:30`) on load. Daily aggregations are grouped strictly by IST calendar date (`date_ist`). |
| **DATA-02** | **Missing Treated as Zero** | **CRITICAL** | Open-Meteo Pune series starts June 1, 2015. Treating January–May 2015 as zero rainfall would artificially lower climatological baselines, distort drought percentiles, and cause erroneous false-negative anomaly detections. | In `src/data/loader_openmeteo.py`, a complete hourly index starting `2015-01-01` is constructed in UTC and converted to IST. Unobserved timestamps retain `np.nan` values and are tagged with `quality_flag = FLAG_MISSING`. Sums over missing periods evaluate to `NaN`, never zero. |
| **DATA-03** | **Grid Cells Outside Pune District Boundary** | **HIGH** | The provided IMD file spans 40 grid cells at 0.25° resolution ($18.0^\circ-19.0^\circ\text{N}, 73.0^\circ-74.75^\circ\text{E}$). Cells west of longitude $73.4^\circ\text{E}$ lie across the Western Ghats crest in the Konkan coastal plains (Raigad/Thane/Ratnagiri districts) where rainfall is 3× to 5× higher. Cells at latitude $18.0^\circ\text{N}$ lie south in Satara/Solapur districts. Conflating these cells with Pune district would trigger massive false alarms. | Explicit cell-centre classification rule implemented in `src/data/loader_imd.py`. Partitions the 40 cells into 24 in-district cells and 16 excluded cells with physical reasons (`west_of_ghats_konkan`, `south_of_district_satara_solapur`). Excluded cells are shown with distinct hollow squares on the map and excluded from district aggregations. |
| **DATA-04** | **Extreme Rainfall Values Clipped or Deleted** | **HIGH** | The IMD dataset contains 16 extreme records exceeding 300 mm/day (e.g. 465.6 mm/day on 2021-07-23 at $18.0^\circ\text{N}, 73.5^\circ\text{E}$). Naive anomaly filters might delete or clip these as sensor errors, erasing catastrophic historical floods. | In `src/data/loader_imd.py`, values $> 300\text{ mm/day}$ are tagged `FLAG_EXTREME_VERIFY` with the descriptor *"extreme, plausible Western Ghats, verify"*. Values are strictly preserved without clipping or alteration. |
| **DATA-05** | **Unit Confusion (mm/h vs. mm/day)** | **HIGH** | Open-Meteo records intensity in mm/hour, while IMD records daily totals in mm/day. Direct aggregation without unit reconciliation produces order-of-magnitude errors in accumulation metrics. | Schema enforcement in `src/data/schema.py` explicitly tracks `unit: mm/h` vs `unit: mm/day`. Hourly sums are calculated over $1\text{h}, 3\text{h}, 24\text{h}, 72\text{h}$ windows; daily values are standardized to mm/day. |
| **DATA-06** | **One Source Dominating / Silent Averaging** | **HIGH** | IMD and Open-Meteo disagree on individual days (Pearson correlation $\approx 0.42$). Silently averaging them masks critical disagreement, creating unwarranted confidence in conflicting estimates. | In `src/data/evidence_builder.py`, the `get_source_agreement()` method monitors absolute delta and ratio. Significant divergence ($> 30\text{ mm}$) penalizes belief confidence by up to $35\%$ rather than averaging the data away. |
| **DATA-07** | **Live API Outage / Network Failure** | **HIGH** | When operating in secure environments or during field telecommunication outages, unhandled HTTP exceptions can interrupt dashboard requests. | In `src/data/live_adapter.py`, the adapter incorporates disk caching (`data/cache/`) and an `OFFLINE-DEMO` fallback. The React/FastAPI application labels these states; demo data is not operationally authoritative. |
| **DATA-08** | **Landslide Records Over-Fitting / Small Sample ML Training** | **MEDIUM** | NASA GLC contains only 3 confirmed events in Pune district. Attempting to train machine learning classifiers on 3 events causes catastrophic over-fitting. | NASA GLC data is restricted strictly to: (a) sanity checking historical deluges, and (b) a weak inverse-distance spatial prior. The UI prominently displays: *"Never train a predictive model on sparse GLC records"*. |
| **DATA-09** | **Stale Data Treated as Fresh** | **MEDIUM** | IMD gridded data arrives with a reporting lag (default $T+1\text{ day}$). Using yesterday's data as if it were real-time today without disclosure misleads crisis controllers. | Every record carries a modeled lag assumption and provenance tag (`PROVIDED-DATA`, `LIVE`, `CACHED`, `FORECAST`, `ASSUMPTION`). Modeled lag is user-editable in the sidebar. |

## 2. Decision Logic & Algorithmic Audits

| ID | Issue Description | Severity | Hazard / Operational Risk | Architectural Fix & Proof |
| :--- | :--- | :--- | :--- | :--- |
| **DEC-01** | **Duplicate or Conflicting Action Ladders** | **CRITICAL** | Multiple conflicting ladders (e.g. 3-state vs 4-state vs raw threshold logic) cause contradictory action recommendations across dashboard panels. | Unified 4-level enum established across `src/policy/policy.py`: `WATCH (0) < PREPARE (1) < ALERT (2) < ESCALATE (3)`. All disparate decision logic consolidated into `Policy.step_decision()`. |
| **DEC-02** | **Action Flapping (Flip-Flopping Under Noise)** | **CRITICAL** | Oscillating around a threshold (e.g. $P(\text{CASCADE}) \approx 0.50$) flips the action between PREPARE and ALERT repeatedly, confusing emergency personnel and eroding trust. | Strict asymmetric hysteresis implemented: escalation occurs immediately upon crossing a higher risk threshold, while de-escalation requires $k_{\text{down}} \ge 2$ consecutive intervals below the threshold. Tested and verified in unit test suite. |
| **DEC-03** | **Unconfirmed Automated ESCALATE** | **CRITICAL** | Automatically triggering siren dispatch and public evacuation without human verification risks municipal liability, panic, and false evacuation costs. | ESCALATE is designated as a **RECOMMENDATION ONLY**. The UI renders a dedicated authorization banner requiring an authorized officer to press `CONFIRM ESCALATE & LOG DISPATCH`. The confirmation is permanently recorded in the ledger. |
| **DEC-04** | **Broken or Tamperable Audit Trail** | **HIGH** | Decision logs stored as unverified mutable arrays can be altered post-incident during inquiry proceedings. | Cryptographic SHA-256 hash chaining implemented in `src/ledger/ledger.py`. Every entry chains `prev_hash` to compute `hash`. Built-in `verify()` function validates genesis-to-tip integrity. |
| **DEC-05** | **Cry-Wolf Fatigue Ignored** | **MEDIUM** | Repeated false alarms cause civic desensitization. When real crises occur, public compliance drops. | Cry-wolf fatigue state $f \in [0, 1]$ tracks cumulative unmitigated false alarms. High fatigue scales false-alarm cost $c_{\text{fa}} \cdot (1 + \gamma \cdot f)$, elevating the evidential bar required to issue subsequent alarms. |
| **DEC-06** | **Unvalidated CostModel Parameters** | **MEDIUM** | Treating uncalibrated economic cost parameters ($D, \rho, c_{\text{fa}}$) as ground truth misleads financial controllers. | All cost parameters are explicitly tagged `ASSUMPTION: unvalidated CostModel parameters, not empirical economic costs`. |

## 3. User Experience & Transparency Audits

| ID | Issue Description | Severity | Hazard / Operational Risk | Architectural Fix & Proof |
| :--- | :--- | :--- | :--- | :--- |
| **UX-01** | **Taluka-Level Claims Without Administrative Polygons** | **HIGH** | Claiming taluka-level boundaries without shapefiles or administrative mapping creates false geographic precision. | Spatial unit is strictly defined as IMD grid cells. Taluka labels are tagged `DATA NOT PROVIDED: nearest taluka proxy` based on cell-centre proximity. |
| **UX-02** | **Missing Provenance Tags** | **MEDIUM** | Analysts cannot distinguish between ground observations, satellite reanalysis, numerical model forecasts, or engineering assumptions. | Standard provenance tag chips rendered on every metric: `PROVIDED-DATA`, `LIVE`, `CACHED`, `FORECAST`, `ASSUMPTION`. |
| **UX-03** | **Black-Box Alerting Without Plain Rationale** | **MEDIUM** | Displaying "PREPARE" without explanation leaves crisis commanders hesitant to commit emergency resources. | Engine generates a plain-language operational rationale (e.g. *"PREPARE because P(CASCADE)=0.42 > 0.35 and 3-day rainfall is 162.4 mm (top 5% for this cell)"*) and displays the exact next threshold to reverse or escalate. |
| **UX-04** | **Static Un-Zoomable Charts** | **LOW** | Static Matplotlib charts prevent operators from zooming into inflection hours or inspecting specific cell time-series. | All static graphics replaced with interactive Plotly figures supporting range selectors, unified hover tooltips, and pan/zoom. |
| **UX-05** | **Cluttered Sidebar with Numbered Headings** | **LOW** | Overloaded sidebars with non-standard numbered headers increase cognitive load during emergencies. | Reorganized into a clean, grouped control panel: Operating Mode, Replay Dates, Cell Selector, Guided Demo Tour, and a collapsed Advanced Settings expander. |
